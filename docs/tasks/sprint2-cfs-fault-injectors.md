# Sprint 2: cFS fault injectors

- **Sprint:** 2: cFS fault injection and log capture *(title pending Ben's approval)*
- **Owner:** Ben's agent
- **Branch:** `feat/cfs-fault-injectors`
- **PR title:** `feat(faults): add three cFS fault injectors`

## Goal
Implement three fault classes from `configs/fault_classes.yaml` that run against the live `orbitlog-cfs` container (cFS v7.0.1). Each one subclasses `FaultInjector` and writes and fsyncs `label.json` **before** the fault is triggered (see the add-fault-class skill).

## Classes chosen
| Class (YAML name) | How to trigger it | Expected cFS evidence (v7.0.1 source) |
|---|---|---|
| `table_load_validation` | Send `CFE_TBL_LOAD_CC` with a `SAMPLE_APP.ExampleTable` file whose `Int1` is greater than 10, then `CFE_TBL_VALIDATE_CC` | `SAMPLE_APP_TblValidationFunc` rejects `Int1 > SAMPLE_APP_PLATFORM_TBL_ELEMENT_1_MAX` (default 10) in `apps/sample_app/fsw/src/sample_app_utils.c`. TBL raises `CFE_TBL_VALIDATION_ERR_EID` (96) |
| `sb_pipe_full` | Send a burst of `SAMPLE_APP` NOOP commands faster than the app drains its pipe | The command pipe depth is 32 (`DEFAULT_SAMPLE_APP_PLATFORM_PIPE_DEPTH`, `sample_app_internal_cfg.h`). SB raises `CFE_SB_Q_FULL_ERR_EID` (25), "Pipe Overflow,MsgId 0x%x,pipe %s,sender %s" (`cfe_sb_priv.c`), and `MsgLimitErrorCounter` goes up |
| `cfs_app_crash_restart` | Make an app exit with an error, then let it be restarted (see the options below) | ES raises `CFE_ES_ERREXIT_APP_INF_EID` (14) or `CFE_ES_ERREXIT_APP_ERR_EID` (33) for an error exit, and `CFE_ES_RESTART_APP_INF_EID` (10) for the restart. HS is in `MISSION_GLOBAL_APPLIST`, but its default app-monitor table (`apps/hs/fsw/tables/hs_amt.c`) only watches cFE core apps with `HS_AMTActType_NOACT` |

Why these three: they are the faults that only exist inside flight software, so they are the cFS part of the benchmark. Satlyt's flown scenarios (out-of-memory, sensor failure) correspond to `oom_alloc_failure` and `i2c_sensor_nack`. Those run on the Linux host side and are scheduled for Sprint 3, so they aren't in this brief.

## Context
- docs/plan.md §4 (dataset) and §3 (the model must output `root_cause_class` and `component`).
- Facts checked in the nasa/cFS v7.0.1 sources (submodules at that tag):
  - The startup script is generated by `sample_defs/generate_startup.cmake`. It always starts `sch_lab`, `ci_lab`, `to_lab` and `sample_app`, plus the global apps, including `hs`.
  - `ci_lab` takes commands over UDP, on port 1234 by default (`DEFAULT_CI_LAB_MISSION_BASE_UDP_PORT`).
  - Command topic IDs: ES 6, TBL 4, SAMPLE_APP 0x82. In this non-EDS build they **should** map to MsgIds 0x1806, 0x1804 and 0x1882 (0x1800 | topic). **Verify** this against the generated headers in the built image before relying on it.
  - The function codes are `CFE_ES_RESTART_APP_CC`, `CFE_ES_STOP_APP_CC`, `CFE_TBL_LOAD_CC` and `CFE_TBL_VALIDATE_CC`. Read their numeric values from `*_fcncodes.h` in the image. Don't guess them.

## Steps
1. **Command sender:** add `src/orbitlog/cfs/cmd.py`, a small CCSDS command builder (primary header, function code and checksum) plus a UDP sender. It runs inside the container (`docker exec ... python`) or on a published port (`-p 1234:1234/udp`). Test the packet bytes in a unit test, without needing the container.
2. **Container helper:** `start()`, `stop()`, `exec()` and `is_operational()` (wait until the log shows `CFE_ES_Main entering OPERATIONAL`). Injectors restart a fresh container for each case, so cases don't leak into each other.
3. **`table_load_validation`:**
   - Make the bad table at image build time. Copy `sample_app_tbl.c` with a seeded `Int1` (11 to 1000), build it with the bundle's table tool (elf2cfetbl), and stage it under `/cf`.
   - The label's `injected_param` records `Int1` and the file name.
4. **`sb_pipe_full`:**
   - Send N NOOPs (N is chosen by the seed and is greater than the pipe depth) in one tight burst.
   - **Risk:** sample_app may drain the pipe fast enough that it never overflows. If so, use a larger burst, or send while the app is busy, for example during a table load. Document what actually works.
   - If none of these overflow it, mark `trigger_status: failed`. Don't fake an overflow.
5. **`cfs_app_crash_restart`:** pick the simplest option that produces real ES/HS events, and write down why.
   - (a) Add a small HS app-monitor table entry for `SAMPLE_APP` with a restart action, then stop the app from checking in.
   - (b) Send `CFE_ES_RESTART_APP_CC` after an injected error exit.
   - (c) Add a tiny `fault_app` to the image with a command that makes it exit with an error.
   - Option (a) is the most realistic.
6. Register the three classes under their YAML names, using `component` values such as `cfs.tbl.sample_app`, `cfs.sb.sample_app` and `cfs.es.sample_app`.
7. Tests:
   - Unit tests (packet building and seed determinism) run in CI.
   - End-to-end tests need Docker and are marked `@pytest.mark.cfs`. They're skipped by default (add `make test-cfs`), so `make test` still passes without Docker.
